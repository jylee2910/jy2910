# 인수인계서 — 새 채팅에서 그래픽 전면 재작성용

> 새 세션은 이 문서를 먼저 읽고 시작한다. 이 문서 하나에 지금까지의 요구사항·피드백·교훈·재사용 가능한 코드가 정리되어 있다.
> 현재 코드: 브랜치 `claude/magical-cori-xsndc9`, 폴더 `crystal-rpg/` (참고용으로 보존, 새 버전은 새 폴더 권장)

## 1. 무엇을 만드는가 (원래 요청 요약)

**"파이널판타지 레조넌스" 스타일의 HD-2D 턴제 RPG 미니판** — 웹(three.js), 모바일 세로 + PC.

- 스타일·시스템만 참고. **이름·캐릭터·세계관·그림은 전부 오리지널** (파판 고유명사·몬스터·캐릭터 금지)
- 외부 애셋은 **라이선스가 명확한 것(CC0 등)만**. 출처와 라이선스를 `CREDITS.md`에 기록
- 콘텐츠: 마을 1(NPC·상점 매매·여관·퀘스트), 월드맵, 던전 1~2 + 최종 보스(페이즈 전환 연출), 처치/수집 퀘스트
- 파티 5종: 검사(레온), 마법검사(카일), 힐러(세라), 용기사(리아), 수호기사(브란) — 장착 가능한 무기 종류가 다름
- **핵심: 어빌리티 시스템.** 무기에 어빌리티가 붙음 → AP로 숙련 → 영구 습득 → 제한된 코스트 슬롯에 등록(액티브/패시브), 공명(시너지), 약점/내성. 루프 = "무기 수집 → 숙련 → 습득 → 빌드"
- 전투: 턴제 커맨드, 행동 순서 표시, 타격감(데미지 숫자·크리티컬·파티클·히트스톱·흔들림·넉백·마무리 연출), 약점 공격으로 BREAK
- 경험치·레벨·장비·골드, localStorage 저장(try/catch)
- 고전 JRPG 파란 창 + 손가락 커서, 한국어 UI
- 기술 조건:
  - three.js 0.170.0을 jsdelivr importmap으로 로드
  - CSS에 `[hidden]{display:none !important}`
  - 단계별로 커밋·푸시하고 `PROGRESS.md`를 계속 갱신
  - 완성 후 Artifact로 게시

## 2. 사용자 피드백 이력 (반드시 반영)

| 차수 | 피드백 | 상태 |
|---|---|---|
| 2차 | 간헐적으로 멈춤(키 입력 불가) | 수정됨 (§6 교훈 1) |
| 2차 | 도트 그래픽이 아쉽고 지형이 평평함, "스팀에 출시될 법한 퀄리티" | 높이 지형으로 개선했지만 **여전히 불만** |
| 2차 | 캐릭터가 물렁하고 캐릭터성이 없음 | 3D 리그로 바꿨지만 **여전히 불만** |
| 3차 | 캐릭터가 허접하고 애들 같음, 프로처럼 멋있게 | 미흡 |
| 3차 | 기술 이펙트·캐릭터 모션을 역동적으로 | 컷인·잔상·원소 이펙트로 개선 |
| 3차 | 대상 선택이 잘 안 보임, **아이템이 맨 위 캐릭터에게만 들어감** | 수정됨 |
| 3차 | 모바일은 줌아웃, 이동이 한 칸씩 끊김 | 자유 이동·조이스틱·줌 단계로 수정됨 |
| **4차(이번)** | **그래픽 전반이 허접 → 기존 토대에 덧붙이지 말고 그래픽을 갈아엎을 것** | **새 채팅에서 할 일** |
| **4차** | **월드맵도 메뉴 클릭이 아니라 자유롭게 돌아다니게** | **새 채팅에서 할 일** |
| **4차** | **상호작용 오브젝트 신호가 없음.** 가까이 가면 "!" 같은 표시가 떠야 함. 단, 멀리서 빛나면 안 됨(탐색해서 찾는 맛) | **새 채팅에서 할 일** |

사용자 성향 메모:
- 결과물의 "격"을 중시한다. 기능이 되는 것보다 **첫인상의 그래픽 품질**로 판단한다.
- 덧대기식 개선을 싫어한다.
- 모바일로 확인한다.

## 3. 새 버전 요구사항 (이번에 추가된 것)

1. **그래픽 전면 재작성.** 지금의 절차적 도형 캐릭터와 타일 블록 지형은 쓰지 않는다. 방향은 §5에서 고른다.
2. **월드맵 자유 이동.** 필드처럼 캐릭터를 직접 조작한다.
   - 지형 위를 걸어 다니다가 마을·던전 입구에 닿으면 진입한다.
   - 걷는 동안 랜덤 인카운터가 일어나고, 지역별로 조우 테이블이 다르다.
3. **상호작용 표시.**
   - 플레이어가 반경(약 1.5m) 안에 들어오고 그쪽을 바라보면, 대상 머리 위에 "!" 말풍선이나 버튼 아이콘이 뜬다.
   - 모바일은 그 아이콘을 탭하면 실행한다.
   - 상자·NPC·조사 포인트·출입구 모두 해당된다.
   - 멀리서 보이는 발광이나 마커는 금지한다.
4. 기존 요구(§1)와 3차까지 반영한 기능은 유지한다:
   - 대상 선택 패널과 마커
   - 아이템 대상 지정
   - 기술 컷인
   - 자유 이동과 가상 조이스틱
   - 줌 단계

## 5. 그래픽 방향 (새 채팅 시작 시 먼저 결정)

**권장: CC0 3D 애셋(glTF와 스켈레탈 애니메이션) + HD-2D 후처리**

- 근거: 프리미티브 조립으로는 "프로 같은" 캐릭터가 안 나온다는 것이 3번의 시도로 확인됐다. 사람이 만든 모델과 애니메이션이 필요하다.
- 후보: KayKit(Kay Lousberg, CC0, 판타지 캐릭터·던전·숲 키트, 애니메이션 포함), Quaternius(CC0, 몬스터·RPG 캐릭터·자연물), Kenney(CC0). 정확한 라이선스는 받을 때 각 팩의 License 파일로 확인한다.
- 화면 구성:
  - 3D 디오라마 지형: 하이트맵 메시 + 자연물·건물 키트
  - 틸트시프트/DOF, 블룸, 그림자
  - 캐릭터: 실제 3D 모델을 그대로 쓰거나 낮은 해상도로 렌더해 도트 질감을 준다(HD-2D 느낌). 어느 쪽인지 사용자에게 시안을 보여주고 고른다.
- 지형: 타일 블록 대신 **하이트맵 기반 연속 지형 + 텍스처 스플랫 + 흩뿌린 소품**을 쓴다. 맵 데이터도 타일 문자열이 아니라 "높이 이미지 / 영역 마스크 / 오브젝트 배치 목록"으로 바꾼다.

**네트워크 사정 (2026-10 기준 이 컨테이너)**

| 접속 | 상태 |
|---|---|
| `cdn.jsdelivr.net`, `unpkg.com`, `kenney.nl`, `quaternius.com` | 막힘 |
| `raw.githubusercontent.com`, `registry.npmjs.org` | 열림 |

- 애셋은 GitHub에 올라간 CC0 팩을 받거나, 사용자가 zip을 저장소에 커밋해 주는 방식으로 들여온다.
- 받은 애셋은 저장소(`crystal-rpg2/assets/`)에 넣어 함께 게시한다. Artifact는 파일당 15MB, 한 번 게시에 64MB 제한이 있으니 glTF는 압축(meshopt/draco)하거나 필요한 것만 추린다.
- 막힌 사이트를 열려면 환경의 네트워크 설정에서 허용 도메인을 추가해야 한다.

## 6. 교훈 (같은 실수 반복 금지)

1. **멈춤 버그의 원인은 애니메이션 콜백 대기다.** 전투 연출이 `onHit`/`onEnd` 콜백을 `await`하는데, hit 프레임이 없는 애니(guard)는 콜백이 영영 안 와서 전투가 정지했다.
   - 애니를 바꿀 때는 대기 중인 콜백을 반드시 먼저 실행한다.
   - 루프 애니는 onHit를 즉시 호출한다.
   - 모든 연출 await에 안전장치(타임아웃)를 둔다.
   - 메인 루프는 try/catch로 감싼다.
2. PointLight에 `decay`가 undefined면 NaN이 나서 화면 전체가 검게 된다.
3. 셰이더는 씬 진입 시 `compileAsync`로 미리 컴파일한다(첫 프레임 끊김 방지).
4. 사라진 DOM의 메뉴 핸들러가 입력 스택에 남으면 키 입력이 막힌다 → `input.prune()`.
5. 이펙트를 겹치면 블룸 때문에 쉽게 하얗게 타버린다. 가산 합성은 불투명도를 0.5~0.6 수준으로 낮춘다.
6. 전투 카메라를 너무 붙이면(5유닛 이하) 파티클이 화면을 덮는다.
7. 전투는 파티 3인 기준으로 배치되어 있다(`party` 파라미터 최대 3).
8. 헤드리스 크롬은 소프트웨어 GL로 약 3fps다. 연출 타이밍 확인은 테스트 훅(`scene.hitCount` 등)으로 프레임을 잡는다.

## 7. 테스트 방법 (jsdelivr가 막혀 있으므로)

```bash
# 1회 준비: 아무 폴더(스크래치패드)에서
npm i three@0.170.0
# 스크린샷: jsdelivr 요청을 로컬 node_modules/three 로 돌려줌
SP=<그 폴더> ROOT=<게임 폴더> node crystal-rpg/tools/test/shot.mjs "index.html?test=battle&foes=slime,wolf&party=leon,sera,bran&lv=5" out.png 960 540 6000 "<page에서 실행할 JS>"
# 결과는 $SP/shots/out.png. AFTER=0 이면 eval 후 대기 없이 바로 촬영
```

- `tools/test/flow.js`: 키 입력 헬퍼 `__p('Enter')`, `__w(ms)`, `__newgame()`, `__mash(조건)`. eval 문자열 안에 `$(cat flow.js)`로 넣어 쓴다.
- 테스트 URL(현재 버전): `?test=battle&foes=..&party=..&lv=..&theme=field|forest|cave`, `?test=field&map=forest&x=5&y=17`.
- 디버그 전역: `window.__app`(현재 씬), `window.__G`(상태).
